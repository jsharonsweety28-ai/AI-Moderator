- [x] **1. Classifier + eval harness** — `lib/moderation/` (client with fail-closed errors + call logging + disk cache), AI #1 scoring prompt, `/api/moderate` route, 49-case labeled set, `npm run eval` with threshold grid-search

All LLM outputs pass a code-side script/language gate (M3 drifts languages with thinking disabled — retry once with explicit directive on mismatch).
- [x] **5. Moderator dashboard** — `/mod`: main queue (ambiguous middle, 10-min timeout that fails closed + tells the author) and a separate low-priority severe-appeals lane. Approve/uphold write `reviews` + `signals`. Live via Realtime **broadcast** (server announces, pages refetch server-filtered — RLS keeps anon table subscriptions dark). All four review outcomes browser-verified: approve → public, uphold → stays hidden + author told, timeout → expired + author told, appeal → waits with no deadline.
- [x] **6. Report / block / mute / remove** — quiet action row under others' comments; `blocks` + `reports` + `signals` (target_* signals only when the actor is the post's author), `negative_reactions` bumped on the relationship; mute/block filter the viewer's feed
- [x] **7. Pile-on + tension + shield** — per-minute sweep (instrumentation.ts interval; `/api/jobs/pileon` for Vercel cron): decay 10%/min, fire only on burst + mostly-negative + mostly-outsiders + cliff + M3 similarity. Shield engages at tension ≥ 0.6 for the target only: hides stranger comments scoring ≥ 0.05 (near-zero on purpose — the pile is individually-mild), Summarize primary (counts/categories/never quotes, covers blocked threats too), Show them secondary, per-user toggle in a cookie. Extremes auto-forward to the mod severe lane as evidence. Demo: `npm run pileon` (idempotent).
- [ ] **8. Freeze-out + co-occurrence** — nightly GROUP BY queries. Cut first if time runs short.
- [x] **9. Deployed to Vercel** — production: https://redraft-nine.vercel.app (also redraft-ai-mod.vercel.app; project `redraft` on the user's Hobby account). Verified live: feed, /api/moderate (shipped .llm-cache reads work — cached inputs return identical results; fresh inputs hit MiniMax live), /mod with both severe items. Notes: generated deployment URLs are behind Vercel's Standard Protection — use the alias domains; team env policy forbids non-sensitive NEXT_PUBLIC project vars, so server code reads `SUPABASE_URL` (project var) and NEXT_PUBLIC values are passed as `-b` build flags on deploy; the per-minute sweep does NOT run on Vercel (Hobby cron is daily) — during demos run `npm run pileon` locally, it writes to the shared Supabase and the deployed site picks it up.
